# V1.1.9 更新日志

## 修复随机图床失效

1.1.8 收紧安全边界时把背景图床限制为三个固定域名，用户此前配置的自定义图床被拦在请求之前，表现为背景不再刷新。本次恢复自定义图床能力，同时保留 1.1.8 引入的全部网络防护。

## 主要变更

1. 图床域名改为「输入即授权」：填入任意 HTTPS 图片地址时弹出确认，确认后域名写入 `trustedImageHosts` 并长期生效。
2. 内置 Picsum 域名保持开箱可用，不需要额外授权。
3. 新增非公网地址拦截：环回、私有网段、链路本地（含云 metadata）、唯一本地地址等一律拒绝，且该规则优先于用户授权列表。
4. 图片下载总超时从 15 秒放宽到 180 秒，连接超时单独收紧为 10 秒。实测部分图床速度仅 9-45 KB/s、单图可达 1.2 MB，旧超时会在慢速大图上间歇性失败。
5. 按文件头魔数判定图片真实类型，不再盲信响应头。实测存在图床声明 `image/png` 实际返回 JPEG 的情况，旧逻辑会写出错误的 data URL 前缀。
6. 网络错误改为展开完整 source 链并附中文说明，替代原先只显示 `error sending request` 的无信息量提示。
7. 图床加载失败原因在设置页显示；下载超过 8 秒提示仍在进行中，避免误认为卡死。
8. 界面版本号改为构建期从 `package.json` 注入，不再硬编码。

## 保留的安全边界

本次未放宽以下 1.1.8 引入的限制：

1. 强制 HTTPS、锁定 443 端口、禁止 URL 携带凭据。
2. 重定向逐跳复核域名，最多 5 跳。
3. 响应内容类型校验与 10 MB 大小上限。
4. CSP `connect-src` 仅保留 GitHub 更新 API；`assetProtocol.scope` 仍限定在应用数据目录。
5. 图片获取继续走 Rust HTTPS 客户端，默认路径不启动 PowerShell。

## Workflow 适配

1. 发布版本已统一到 `1.1.9`，`package.json`、`Cargo.toml`、`tauri.conf.json` 及两个 lock 文件同步。
2. `v1.1.9` tag 可通过 release workflow 的版本匹配检查。
3. 前端测试、Rust 测试和 `cargo fmt --check` 门禁均已在本地通过。

## 验证重点

1. 设置页填入自定义 HTTPS 图床地址，应弹出授权确认；确认后可成功刷新背景。
2. 重启应用后授权域名仍然生效，背景自动加载。
3. 填入内网地址（如 `https://192.168.1.1/x.jpg`）应被拒绝并提示原因。
4. 填入非 HTTPS 地址应被拒绝。
5. 慢速图床下点击「刷新预览」，8 秒后应出现下载中提示而非无反馈等待。
6. 侧边栏底部与设置页「关于」显示的版本号应为 v1.1.9。
