# 时间块日程规划功能规划书

> 本规划书以"时间块"工作法为设计依据，目标是把现有的"待办日程表"升级为可以排满一天、并能随时重排的时间轴视图。本文件为草案，第 8 节的五项决策待确认后再进入实施。

> 2026-11-03 后续需求调整：用户要求可规划范围改为全天 24 小时。每天（包括周末）统一显示 00:00–24:00；工作日和工作时段只作背景提示。覆盖统计与周回顾均按全天计算，不再单列工作时段外事项。结束时间允许 24:00，开始时间仍需早于 24:00，跨日期事项仍需分开安排。以下原始阶段规划中相关工作时段限制以本条调整为准。

## 1. 背景与目标

现有"待办日程表"支持按日期管理事项，事项可带可选的开始和结束时间，并按"逾期 / 当日 / 已完成"分组。但它没有"一天的时间轴"视角：看不出哪些时段已被安排、哪些是空白，被打断后也没有快速重排剩余时间的手段。

本功能要达成的目标：

1. 每个工作日有一页时间轴，覆盖完整工作时段。
2. 时间块最短 30 分钟，一个活动可以占据一个或多个方格。
3. 通用任务块可挂载子任务清单，对应"引线到右侧"的做法。
4. 工作时段内每一分钟都能看出归属，空白可见且可处理。
5. 被打断后，能从当前时刻快速重排剩余时间。
6. 备用块吸收超时；备用时间未用到时可转作其他事项。
7. 记录实际用时，帮助逐步校准估时。

非目标（v1 不做）：

1. 与 Outlook、Google 等外部日历同步。
2. 多人共享或团队视图。
3. 跨午夜的时间块。
4. 自然语言录入。

## 2. 方法要素与功能映射

| 方法要素 | 对应功能 | 说明 |
|---|---|---|
| 每个工作日翻开新的一页 | F2 时间轴 | 按日期展示，默认今天，复用左侧月历 |
| 左侧每隔一行标注一个小时 | F2 | 30 分钟一行，整点标注小时 |
| 方格最短半小时 | F4 | 新建和拖拽默认吸附 30 分钟 |
| 方格不必都有活动 | F6、F9 | 允许空白；提供休息块 |
| 任务方格引线到右侧列出小任务 | F11 | 块的子任务清单，显示在右侧面板 |
| 每一分钟都有归属 | F6 | 覆盖统计，空白一键转为备用块 |
| 被打断后修改剩余时间 | F13 | "从现在重排" |
| 备用方格 | F10 | 超时占用备用块；未用时转为其他事项 |
| 估时要保守 | F16、F17 | 计时并统计估计与实际的偏差 |

## 3. 现状（基于代码）

- 入口：待办窗口是运行时创建的（`src-tauri/src/utils/shortcuts.rs` 中的 `show_or_create_todo_window`），窗口 label 为 `todo`，界面在 `src/TodoWindow.vue`。
- 数据：`TodoItem` 已有 `startTime` / `endTime`（`HH:mm`），但只用于排序展示，不参与空白和冲突计算。
- 持久化：`todos` 经 `persistenceService` 调用 `write_persisted_data` 写入 `todos.json`，envelope 的 `schema_version` 当前固定为 1。
- 已有能力：月历与快捷日期、快速添加、逾期 / 当日 / 已完成分组、搜索跳转（`select-todo` 事件）、清理历史。
- 输入精度：时间输入的步长是 15 分钟（`step="900"`），与 30 分钟方格规则不一致，见决策 D1。
- 可复用：`show_notification` 命令已存在（基于 `tauri-plugin-notification`），块开始提醒不需要新增依赖。
- 缺口：时间轴视图、子任务、块类型、重排、计时、当前时刻指示。

## 4. 产品原则

1. 重排是常态。重排是一等操作，不计入任何"失败"统计。
2. 空白是允许的。不强制填满一天，但空白必须可见，让用户有意识地做决定。
3. 默认安静。提醒默认关闭，不弹窗打断用户。
4. 兼容旧数据。已有的 `todos.json` 无需手动处理即可读取。

## 5. 功能需求

### 5.1 P0：时间轴（MVP）

- F1 工作时段：默认周一至周五 09:00–18:00，可在设置中修改。新增配置遵循 CLAUDE.md 的 New Setting 流程。
- F2 时间轴视图：待办窗口内新增"列表 / 时间轴"切换。每行 30 分钟，整点标注小时，当前时刻显示横线。
- F3 块渲染：有 `startTime` 和 `endTime` 的事项渲染为块，高度与时长成比例；已完成的块灰显。
- F4 创建与编辑：点击或拖拽空白区域创建块（吸附 30 分钟）；拖动块体移动；拖动下边缘调整时长；点击块打开编辑。
- F5 未排期池：没有时间的事项列在时间轴旁，可拖入某个时段。
- F6 覆盖统计：统计范围仅限工作时段。任何块（包括备用块和休息块）覆盖的分钟都视为有归属。顶部显示"已规划 X / Y 小时"，未覆盖的区段斜纹标出，并可一键转为备用块。
- F7 工作时段外的事项：照常保存，在时间轴外以提示条显示，不计入覆盖统计。
- F8 搜索联动：搜索结果跳转时切换到时间轴并高亮对应块（沿用 `select-todo` 事件）。

### 5.2 P1：任务结构

- F9 块类型：`task`（具体活动，默认）、`buffer`（备用）、`break`（休息或午饭）。
- F10 备用块联动：
  - 任务块需要延长 N 分钟时，占用紧随其后的备用块；备用块时长减为 0 时删除。
  - 备用块未用完时，可把剩余时段转为其他事项（从未排期池中选择）。
- F11 子任务清单：任何块都可以添加子任务（标题与完成状态）。选中块时，右侧面板展示清单。通用任务块就是"挂了多个子任务的任务块"。块的完成状态仍需手动切换，子任务只显示进度（如 3/5）。
- F12 快捷插入：一键插入 30 分钟或 60 分钟的休息块；提供午饭预设（默认 12:00–13:00，可修改）。

### 5.3 P2：重排与打断

- F13 从现在重排：
  - 锚点为当前时刻，向上取整到 30 分钟。
  - 锚点之前的块保持不变。
  - 跨越锚点的块截断为锚点之前的部分，剩余部分进入"待重排"池（保留 id 与子任务）。
  - 锚点之后未完成的块同样进入待重排池。已完成的块不受影响。
  - 用户在时间轴上重新摆放后确认写入。
- F14 打断记录（可选）：重排时可选择原因（会议、紧急插入、其他），仅用于回顾。
- F15 变更记录（可选，见决策 D5）：被替代的块以删除线保留在当天的"变更记录"中，便于回顾一天改了几次计划。

### 5.4 P3：估时与回顾

- F16 计时：块可开始和停止计时，累计到 `actualMinutes`。计时起点以时间戳保存（`timerStartedAt`），窗口隐藏或应用重启后不丢失。
- F17 估计偏差：根据已计时块的实际 / 估计比率中位数，在新建块时给出"建议预留 X 分钟"的参考值。
- F18 块提醒（可选，见决策 D4）：块开始前 N 分钟通过 `show_notification` 发送系统通知，默认关闭。
- F19 周回顾（可选）：按天展示本周已规划小时数、实际用时和重排次数。

## 6. 数据模型（草案）

```ts
type TodoBlockKind = 'task' | 'buffer' | 'break'

interface TodoSubtask {
  id: string
  title: string
  completed: boolean
}

interface TodoItem {
  // 现有字段保持不变
  kind?: TodoBlockKind       // 缺省视为 'task'
  subtasks?: TodoSubtask[]   // 缺省视为 []
  actualMinutes?: number     // F16
  timerStartedAt?: number    // F16，毫秒时间戳
}
```

- 兼容策略：新增字段全部可选，在 `normalizeTodoItem` 中补默认值，不做数据迁移，`schema_version` 暂不变。
- 安全网：首次写入新字段前，调用已有的 `persistenceService.backup('todos', reason)` 做一次备份。
- 新持久化类型：若实现 F15 的变更记录，需要新增 `PersistedDataType`，同步修改 Rust 侧枚举和 `tauriAdapter`。
- 设置项：工作时段、工作日、吸附粒度、午饭时段等写入 `AppSettings`。

## 7. 界面与交互

- 布局：左侧月历保留。内容区顶部增加视图切换，时间轴占据主区域。选中块时，右侧展开详情与子任务面板。
- 窗口尺寸：时间轴加右侧面板需要更宽的窗口，尺寸在 `show_or_create_todo_window` 中设置。是否调整见决策 D2。
- 主题：沿用 `applyThemeSettings`。块颜色按 `kind` 区分，亮色和暗色主题下都要检查对比度。
- 键盘：保留 Esc 关闭。N（新建块）、R（从现在重排）等快捷键待确认，不属于 MVP。

## 8. 待确认的决策

请对以下五项做出选择，或直接确认推荐项。

**D1 时间粒度**
- A：严格 30 分钟网格。与方法一致，界面最简单；但已有的 15 分钟时间会被取整，丢失精度。
- B（推荐）：内部保留分钟精度，拖拽和新建默认吸附 30 分钟，手动输入仍允许 15 分钟。不丢数据，同时保留 30 分钟的默认节奏。

**D2 放置位置**
- A（推荐）：在现有待办窗口内增加视图切换。复用日期、搜索跳转和存储，主要成本是加宽窗口。
- B：新建独立的"日程规划"窗口。布局自由，但需要新增 Rust 创建逻辑和前端入口，工作量明显更大。

**D3 块是否允许重叠**
- A（推荐）：不允许重叠，保存时提示冲突。与"每一分钟只属于一个方格"一致。已有的重叠数据仍可显示，但会标记警告。
- B：允许重叠并列显示。约束更宽松，但覆盖统计会更复杂。

**D4 块开始提醒**
- A（推荐）：v1 不做提醒，只显示当前时刻横线。
- B：支持块开始前的系统通知，默认关闭，复用 `show_notification`。

**D5 变更记录**
- A（推荐）：MVP 不保留历史，只保留最终计划。
- B：保留当天的变更记录，需要新增持久化类型。

另外，工作时段默认设为周一至周五 09:00–18:00，如与你的习惯不同请告知。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| `TodoItem` 同时承担待办和时间块，职责变重 | 保持单一实体，新增字段全部可选，P0 不引入新实体 |
| 旧数据的 15 分钟精度与 30 分钟网格冲突 | 采用 D1-B，存储保留分钟精度 |
| 窗口空间不足 | 右侧面板可收起；必要时采用 D2-B |
| 过度规划带来挫败感 | 允许空白；不展示"完成率"之类的惩罚性指标；重排不计失败 |
| 提醒打扰用户 | 默认关闭 |
| 计时数据丢失 | 以时间戳持久化，而非只保存在内存中 |
